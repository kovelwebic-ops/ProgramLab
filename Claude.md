# Фітнес-платформа для тренерів — MVP Specification

## Огляд проєкту

Веб-застосунок (SaaS, десктоп-версія) для тренерів та людей, які тренуються самостійно. Мета — об'єднати в одному місці все, що тренеру потрібно для роботи з клієнтами: конструктор програм тренувань, базу вправ з гнучкими фільтрами (травми/протипоказання/обладнання), CRM клієнтів, розрахунок раціону та трекінг прогресу.

**Ключова відмінність від існуючих рішень** (TrueCoach, Trainerize, TrainHeroic): гнучкий білдер програм із можливістю виключати вправи за фільтрами (група м'язів, обладнання, протипоказання) або вручну — все в одному інструменті, без розкиданого по різних сервісах функціоналу.

## Користувачі

Два незалежні типи акаунтів в одному застосунку, обираються при реєстрації:

1. **Тренер** — веде декількох клієнтів. Клієнти НЕ мають власного логіну — весь функціонал і дані клієнта живуть всередині акаунту тренера, тренер сам вносить всю інформацію (програми, прогрес, виміри, фото).
2. **Самостійний трейні** — тренується сам, веде свою програму і прогрес без тренера.

Обидва типи акаунтів використовують спільне ядро (база вправ, білдер програм, калькулятор раціону), але мають різні кабінети/UI.

## MVP — функціональний обсяг

### 1. Режим роботи (замість авторизації)
- Реєстрації й логіну в MVP **немає** — усе локально, без бекенду й акаунтів
- Режим "Тренер" / "Тренуюсь сам" перемикається прямо в застосунку (як Claude Chat / Claude Code)
- Дані обох режимів живуть в одному локальному сховищі цього браузера

### 2. База вправ
- Сітка карток: фото + назва, група м'язів, обладнання, навантаження на суглоби
- Натискання на картку відкриває редактор (назва, категорії, фото, видалення)
- Фільтрація за групою м'язів / обладнанням / навантаженням на суглоби + пошук
- Ручне виключення конкретної вправи при побудові програми (напр., травма чи протипоказання клієнта)

### 3. Білдер програм тренувань

Два режими на спільній моделі даних, тип обирається в самій програмі:

- **Культуризм** — компактна таблиця: підходи, повтори, вага, % від ПМ.
- **Пауерліфтинг** — вправа-картка з навантаженням (легке/середнє/важке), групою руху
  (ПР/ЖМ/ТГ/ЗФП), кількома блоками роботи й розрахунками: тоннаж, КПШ, середня вага,
  ВІ (відносна інтенсивність), час. Підсумки по дню й по тижню.

Спільне для обох: створення з нуля, готові пресети як стартова точка, додавання/видалення
вправ і днів, обмеження профілю (травми/обладнання/групи м'язів/ручні виключення).

- **Блок роботи** — рядок «вага × повтори × підходи + відпочинок». Культуризм показує один
  блок на вправу, пауерліфтинг — скільки треба (розминочні + робочі підходи різної ваги).
- **ПМ (персональний максимум)** вписується руками по кожній вправі програми. Вага і % від ПМ
  перераховуються одне з одного; при зміні ПМ ваги йдуть за відсотками (плани пишуться у %).
- Один активний шаблон програми на клієнта/трейні, один тиждень. Мікроцикли й періодизація —
  наступний етап (рішення власника: спершу розрахунки на одному тижні).

### 4. Калькулятор раціону
- Розрахунок денної норми калорій та БЖУ (Міффлін — Сан-Жеор: вага, зріст, вік, стать, активність, ціль)
- Норма показується і в грамах, і **на кілограм ваги** (г/кг, ккал/кг) — тренер керує саме цим
- **План на тиждень**: 7 днів, у кожному свій набір приймань їжі, копіювання дня на весь тиждень.
  Обліку по факту немає свідомо — його ведуть у FatSecret, тут тренер складає раціон
- Без бази продуктів: назва, калорії та БЖУ вписуються вручну

### 5. Трекінг прогресу
- Вага тіла (записи в часі)
- Прогрес по вправах (вага × повтори, історія по кожній вправі)
- Фото прогресу (завантаження, перегляд у хронології)
- Графіки по всіх трьох метриках

### 6. Кабінет тренера
- CRM клієнтів: список + картка клієнта (контакти, антропометрія, цілі, травми/протипоказання, нотатки)
- Призначення програми клієнту з білдера
- Ручне внесення прогресу клієнта (вага, вправи, фото)
- Графіки прогресу по кожному клієнту

### 7. Кабінет самостійного трейні
- Власний профіль (цілі, антропометрія)
- Своя програма (той самий білдер)
- Власний калькулятор раціону
- Внесення власного прогресу + графіки

## Орієнтовні сутності даних (для довідки)
- `User` — роль: trainer / trainee
- `Client` (належить тренеру) — контакти, антропометрія, цілі, травми, нотатки
- `Exercise` — назва, група м'язів, обладнання, суглоби під навантаженням, фото
- `ProgramTemplate` — тип (культуризм / пауерліфтинг) + дні → вправи → блоки роботи
- `Max` — ПМ по вправі для профілю (`profile.maxes[exId]`), основа для % і ВІ
- `BodyWeightEntry` — вага, дата
- `ExerciseProgressEntry` — вправа, вага×повтори, дата
- `ProgressPhoto` — фото, дата
- `MealEntry` — назва, калорії, БЖУ, дата
- `NutritionTarget` — розраховані калорії/БЖУ

## Свідомо поза межами MVP
- Окремий логін/портал для клієнтів тренера
- Мобільна адаптація (тільки десктоп у MVP)
- Оплата / підписки / монетизація
- База продуктів харчування для раціону
- Автоматична періодизація програм по тижнях/мезоциклах
- Автоматичні рекомендації прогресії навантажень
- Інтеграції з wearables/фітнес-трекерами

## Технічний підхід

Той самий підхід, що у проєкті FoodCost: **без фреймворків, без збірки, без бекенду**.
Дизайн — мінімальний службовий; редизайн буде окремим етапом у Claude Design, після того
як флоу перевірені реальним використанням. Платформа: десктоп веб-застосунок.

### Файли

| Файл | Що всередині |
|---|---|
| `index.html` | Каркас: сайдбар, контейнер екранів, корінь модалок, тост |
| `styles.css` | Токени кольорів і компоненти (панелі, таблиці, чипи, модалки, графіки) |
| `js/core.js` | Утиліти, модель стану, `localStorage`, модалки, тост, сховище фото (IndexedDB) |
| `js/data.js` | Довідники (групи м'язів, обладнання, суглоби, активність), 36 вправ, пресети, демо-дані |
| `js/chart.js` | Лінійний графік на SVG (`PL.lineChart`) — без зовнішніх бібліотек |
| `js/exercises.js` | Екран бази вправ, фільтри, редактор вправи, модалка вибору вправи |
| `js/programs.js` | Білдер програм, пресети під обмеження, блок обмежень (`PL.restrictionsHtml`) |
| `js/nutrition.js` | Норма калорій і БЖУ (Міффлін — Сан-Жеор), щоденник харчування |
| `js/progress.js` | Вага тіла, результати у вправах, фото + графіки |
| `js/profile.js` | Профіль клієнта / трейні (спільний для обох режимів) |
| `js/clients.js` | Список клієнтів і картка клієнта з вкладками |
| `js/app.js` | Навігація, перемикач режиму, екран «Дані», старт |

Усе спільне живе в одному глобальному об'єкті `PL` (без модулів — щоб працювало з `file://`).
Екрани — `PL.screens.*`, вкладки профілю — `PL.views.*` (приймають профіль: клієнта або `S.self`).

### Дані

- Увесь стан — один об'єкт у `localStorage['pl:state:v1']`, запис відкладений на 300 мс.
- **Фото — окремо в IndexedDB** (`pl-photos`), у стані лежать лише `{id, date}`: у localStorage
  кілька знімків одразу впираються в ліміт ~5 МБ. Перед збереженням стискаються до 1600px / JPEG 0.85.
- Профіль клієнта й профіль самостійного трейні — **однакова структура**, тому вкладки
  «Програма», «Раціон», «Прогрес» — один і той самий код для обох режимів.
- Обмеження профілю (`exclusions`): `joints` (травми), `muscles`, `equipment` + `exercises`
  (виключені вручну). Вони ховають вправи з пошуку й не дають їм потрапити в пресет —
  замість виключеної вправи пресет підставляє дозволену з тієї ж групи м'язів.
- Нове поле в стані → додати дефолт у `PL.normalizeProfile` / `PL.normalize` (дані вже записані
  старими версіями).

### Запуск

Просто відкрити `index.html` у браузері. Для превʼю в інструментах, які не виконують скрипти
з `file://` (Node і Python на машині немає), є PowerShell-сервер: `.claude/serve.ps1`
(конфіг для превʼю — `.claude/launch.json`, порт 8765).
